## 摘要与关联结果

对 7 段入库 pkl（commit `fc0b9be`，`x1_retargeted_motion/`）做 root 水平速度实测（帧间差分 × fps=30 得名义速度；除以各段 `time_scale` 得慢放后真实播放速度）：

| clip | time_scale | 名义 p50/p90 (m/s) | 真实 p50/p90 (m/s) | 步频 (Hz) | root-z 振幅 (cm) | 帧数 |
|---|---|---|---|---|---|---|
| run1_subject2_seg0 | 1.06 | 1.32 / 1.48 | **1.24 / 1.40** | 2.69 | 16.6 | 340 |
| run1_subject5_seg0 | 1.21 | 1.33 / 1.84 | **1.10 / 1.52** | 2.49 | 15.7 | 717 |
| run2_subject1_seg1 | 1.19 | 1.47 / 1.66 | **1.23 / 1.39** | 2.44 | 17.7 | 338 |
| run2_subject1_seg2 | 1.30 | 1.26 / 1.46 | **0.97 / 1.13** | 2.84 | 16.8 | 306 |
| run2_subject4_seg0 | 1.26 | 1.67 / 1.92 | **1.32 / 1.52** | 2.34 | 14.6 | 411 |
| run2_subject4_seg1 | 1.18 | 1.23 / 1.65 | **1.05 / 1.40** | 3.50 | 6.3 | 326 |
| run2_subject4_seg2 | 1.30 | 1.30 / 1.47 | **1.00 / 1.13** | 3.51 | 11.9 | 346 |

三条硬结论：

1. **真实速度带宽仅 0.97–1.52 m/s（p50 全部 ≤1.32，p90 全部 ≤1.52）**——这是慢跑/快走边界速度，不是「奔跑」。若一期验收速度 >1.5 m/s，现有数据无法直接支撑。
2. **名义速度（G1 源）p50 也只有 1.23–1.67 m/s**，低于 README L27 所述切段速度窗下限 1.5 m/s 的直觉预期（切段窗按段落级判定，瞬时中位数更低）——即使撤销慢放，源数据本身也不是高速跑。
3. **速度压缩来自双重机制**：`s_leg=0.7726`（G1→X1 腿长缩放，等效速度需求 ×0.77）+ `time_scale` 1.06–1.30 慢放（×1/ts）。两者叠加后 X1 感受速度 ≈ G1 源速度 × 0.77 / ts 的运动学等效（推断，非直接测量）。

这把 0001-I2 从「需要诊断」升级为「已定量确认：速度带宽不足」，并引出目标定义问题（I11）。

## 论文与实现证据

- 本实测：脚本 `research/studio/idear/20261004_e1_preanalysis_speed.py`（纯 Python raw-unpickler，无 numpy 依赖，本地可复现）；数据 `x1_retargeted_motion/*.pkl`（`frames` 前 3 维为 root pos）。
- 方法说明与局限：名义速度=相邻帧 root 水平位移×30（含噪声，p50/p90 为排序分位）；真实速度口径=名义/ts（假设 time_scale 均匀作用于播放速率，与 README「均匀时间膨胀」一致）；步频=root-z 去趋势后过零计数/2（粗估）；root-z 振幅=max−min（含重心起伏+姿态起伏，偏大估计）。**duty/腾空/攻角未测**（需 FK，见 0002-I10 的 14 项完整表，待 worker 环境）。
- 文献锚点（承接 [R2]）：HumanPlus 的教训——「策略继承训练数据的人类速度分布」，且文中明确 noted limitation 是速度带宽受 demo 制约；EWC 的反例——指令速度从 reference 根运动采样时，策略可外推到片段之外的速度范围（Fig.5）。二者共同指向：**若要超出 1.5 m/s，靠数据不如靠指令条件化的设计**。

## 优先建议

### I11 · 明确一期「奔跑」验收速度的定义与达标路径（项目决策建议）
- **关联结果版本**：0001/I2 + 本实测
- **文件/函数**：数据 `x1_retargeted_motion/*.pkl`（time_scale/s_leg 字段）；worker 的速度指令设计（待建）
- **观测事实**：见上表；真实带宽 0.97–1.52 m/s。
- **机制假设**：数据物理上大概率自洽（run 族 root-z 振幅 6–18 cm 与慢跑相符；与 sprint 族 README 自述的不自洽不同——**推断**，duty 待 FK 确认），问题不在「能不能学」而在「学出来多快」。
- **竞争解释**：①「奔跑」目标本就定义为 1.0–1.5 m/s 慢跑——则本发现仅为口径确认；②训练时按名义速度（不除 ts）时间轴训练，策略实际收敛速度仍会低于名义（物理时间被拉长）——即无论哪种理解，策略真实速度 ≈ 真实口径值。
- **最小改动或诊断实验**：无需实验——需要 worker 一句话确认一期目标速度区间。两条路径供选：
  - **路径 A（推荐）**：一期验收定为「1.2 m/s 稳定慢跑 + sim2sim 通过」，用现有数据；二期补 LAFAN 高速段（源速度 >2.5 m/s 且对 X1 关节速度可行的段）把带宽推到 2.0+。
  - **路径 B**：若一期必须 >1.5 m/s，则数据侧先行：从 LAFAN Run/Sprint 主题重新切段（提高源速度窗下限），并验证 X1 关节速度可行性（需 URDF 限速 × s_leg 换算）——依赖服务器端 G1 csv（README L19 注明未入库）。
- **对照变量**：验收速度区间（A/B 两案）；数据集（现有 7 段 vs 补充段）。
- **预期指标**：路径 A：策略在 1.0–1.4 m/s 指令下 sim2sim 速度误差 <15%（BeyondMimic 真机跑步口径 13.65% 可参考）；路径 B：补充数据后训练速度上限提升幅度。
- **支持/否定条件**：支持=worker 确认 A 后训练收敛且 sim2sim 达标；否定=若按 A 训练后策略实际速度显著超过数据带宽（>1.7 m/s）且稳定——说明指令条件化外推有效（EWC 机制成立），届时路径 B 必要性下降。
- **成本风险**：A 零数据成本；B 依赖服务器资源与切段重跑，且高速段对 X1 关节速度可行性未验证（可能再次触发慢放→速度上限死循环）。
- **worker 的下一步**：确认一期目标速度；若 A，直接进入 E2（run2_subject1_seg2 或 run2_subject4_seg2，真实速度最低最稳）。

### I12 · 训练管线 time_scale 消费口径必须单一固定为「真实口径」
- **关联结果版本**：0001/I2、I3（one-frame-ahead goal）
- **文件/函数**：worker 数据加载器（待建）；pkl 字段 `fps=30, time_scale`
- **观测事实**：7 段 ts 1.06–1.30 各不相同；若加载器统一按 fps=30 重采样，各段等效播放速率被隐式错置 6–30%。
- **机制假设**：正确口径=有效帧率 30/ts（等价于帧间隔 ×ts）；差分 goal（v̂=Δp·30/ts）与速度奖励的 v_ref 都应按此口径，否则 7 段之间速度标定互相矛盾，策略学到的是「平均后的模糊速度」。
- **竞争解释**：若采用 AMP 范式（时间对齐被消除），ts 错置无害——但速度带宽问题仍在（状态分布的速度特征已被慢放改变）。
- **最小改动或诊断实验**：加载器单测：断言 `dt_frame = 1.0/(fps/time_scale)`；输出每段等效帧率表。
- **对照变量**：名义口径 vs 真实口径各训一次短跑（E2 的 ablation 子项）。
- **预期指标**：真实口径下速度跟踪误差更低（若名义口径更高则说明时间轴语义另有约定，需查 GMR 链定义）。
- **支持/否定条件**：支持=真实口径训练的速度跟踪/步态物理量更接近 E1 实测分布；否定=无差异（则 ts 已在数据生成时烧进 frames，需与正本管线核对——README 注明正本在 `tools/x1_pipeline/`，本工作区是归集副本，未提交部分无从核对）。
- **成本风险**：低；但若 ts 语义与我假设相反（如 ts 已应用于帧间隔、直接按 30fps 读即真实），则会双重缩放——单测先行可排除。
- **worker 的下一步**：数据加载器实现 `motion_dt()` 时显式带 ts，并跑该单测。

## 上下游缺口

1. **一期目标速度无书面定义**（I11 的根因）——工作室 mandate 只说「实现奔跑运动控制算法」，速度区间未定，直接影响数据充分性判断与验收标准。
2. **正本管线不在本工作区**：README 注明正本在 `tools/x1_pipeline/`（远端仓库），time_scale 的精确语义（应用于播放还是已烧入帧）本工作区无法核实——worker 可访问正本，应做 I12 的单测核实。
3. **高速数据缺失**：LAFAN Run 主题源数据本身 p50 ≤1.67 m/s（名义），若一期目标 >1.5 m/s，需要 Sprint 主题或外部数据源（如 AMASS 跑步段），且须过 X1 关节速度可行性检查。

## 反证与不确定性

- **[已观测] 速度带宽 0.97–1.52 m/s**：本报告实测，可复现。但步频为 z 过零粗估（误差可达 ±20%），z 振幅含姿态分量；精确值以 worker 环境的 14 项表为准。
- **[推断] run 族物理自洽**：基于 z 振幅与速度-步频搭配的合理性判断，**duty/腾空未测**——若 FK 后 duty<20% 或腾空>0.35 s（慢跑不合理值），则自洽性推翻，I11 路径 A 也需先过滤数据。
- **[推断] time_scale 语义=播放慢放**：与 README「均匀时间膨胀」表述一致，但正本不可及，I12 单测是唯一确证途径。
- **[推断] s_leg 影响速度需求**：腿短 23% 则同角速度线速度低 23%——但重定向后 X1 关节速度是否真的低于 G1（从而允许更高 ts 逆操作）未测，路径 B 的可行性存疑。
- **[未验证] EWC 式指令外推在 X1 上的有效性**：若成立，数据带宽不足可被部分缓解——这正是 I11 否定条件中的情形。
